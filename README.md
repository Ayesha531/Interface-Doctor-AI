# Interface Doctor AI

Phase 1 foundation for DebugMD's Interface Doctor AI: upload a UI screenshot, validate it, run a secure server-side AI diagnosis, and display prioritized findings with visual overlays.

## What is included in Phase 1

- PNG/JPG screenshot upload with file type and 6 MB size validation
- Sample screenshot generator for demos
- Secure Next.js API route for a vision-capable OpenAI diagnosis model
- AI response validation and graceful error messages
- Prioritized findings with severity, explanation, suggested fix, and percentage-based overlay areas
- Loading, empty, success, error, and pending states for the overall product flow
- Clear placeholders for later generation, verification, and saving phases

## Not included yet

- Improved responsive interface generation (Phase 2)
- Before/after comparison (Phase 2)
- Measurable verification checks and report saving (Phase 3)
- Supabase auth/database persistence (Phase 3)

## Setup

Install dependencies:

```bash
npm install
```

Add secrets in the workspace Secrets panel (do not commit secrets in files):

- `OPENAI_API_KEY` — required for real AI diagnosis
- `OPENAI_VISION_MODEL` — optional, defaults to `gpt-4o-mini`

Then run the app:

```bash
npm run dev
```

Open the preview URL and upload a PNG/JPG screenshot or load the sample screenshot.

## Security notes

- AI keys are only read from `process.env` in `app/api/diagnose/route.ts`.
- Uploaded image data is validated on the client and again on the server.
- AI responses are parsed and normalized into a constrained JSON shape.
- The app does not execute any code generated by AI.
- Phase 1 does not persist screenshots or diagnosis results; browser state resets on refresh.
